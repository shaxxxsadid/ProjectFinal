СКЛАД
Резерв:
available -= qty
reserved += qty
quantity не меняется

Отмена:
reserved -= qty
available += qty

Финальное списание:
quantity -= qty
reserved -= qty
available не меняется

Инвариант:
available = quantity - reserved

FEFO:
- сначала партия с ближайшим сроком годности
- просроченные партии не использовать

StockMovement хранит:
- type
- source
- stockId
- productId
- warehouseId
- batchNumber
- quantity
- before
- after
- orderId / orderNumber при наличии
- actorId
- timestamps

ТЕКУЩАЯ ЗАДАЧА — CREDENTIAL REGISTRATION

Важно:
Credentials ВХОД уже есть в:
app/api/auth/[...nextauth]/route.ts

Он:
- принимает email/password
- ищет Users по email
- проверяет user.passwordHash
- bcrypt.compare(password, passwordHash)
- получает роль через Roles.service
- возвращает MongoDB user id
- OAuth не менять

Нужно добавить именно регистрацию.

Желаемый поток:
app/pages/register/page.tsx
→ POST /api/auth/register
→ validation
→ bcrypt.hash(password, 12)
→ default role = "user"
→ Users.create(...)
→ создать credential Account, если это соответствует текущей схеме Accounts/Providers
→ signIn("credentials")
→ redirect в /pages/catalog

Поля формы:
- Имя
- Фамилия
- Email
- Пароль
- Повтор пароля

Минимальная валидация:
- firstName не пустой
- lastName не пустой
- корректный email
- password >= 8 символов
- password === confirmPassword
- email привести к lowercase/trim
- нельзя создать второй User с тем же email

ВАЖНЫЙ СЛУЧАЙ
Если User с таким email уже существует, в том числе создан OAuth:
- НЕ создавать второго пользователя.
- вернуть понятное сообщение:
  «Пользователь с таким email уже существует. Войдите существующим способом авторизации.»

Новый пользователь:
- role = user
- isActive = true
- username можно сделать из firstName + lastName либо по текущей логике проекта
- password хранить только как passwordHash
- plain password никогда не писать в БД и логи
